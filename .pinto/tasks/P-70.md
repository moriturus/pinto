# **Summary**

Allow action items recorded in a Retro or Review to become ordinary PBIs linked to their source child record, so follow-up work uses the existing backlog workflow instead of a second task system.

# **Scope**

- Support action-item promotion from either a Retro or a Review into a normal PBI.
- Preserve the established PBI creation options, including title, body/template, assignee, Sprint assignment, and dependencies where supplied.
- Store a source link containing the child record kind and Sprint-matching ID.
- Display linked action PBIs from the child record while their status remains managed by normal PBI commands.

# **Acceptance Criteria**

- [ ] A Retro or Review action can create a normal PBI with the existing PBI creation semantics.
- [ ] The created PBI retains a machine-readable link to its source Retro or Review.
- [ ] Retro and Review views can show their linked action PBI IDs and current statuses.
- [ ] Action progress is controlled by existing PBI list, show, edit, move, and remove behavior rather than a parallel action-item state machine.
- [ ] Existing PBI workflows remain usable for action PBIs without requiring a Retro or Review-specific status.
