# **Summary**

Allow users to update a Sprint's planned start or end datetime independently through `sprint edit`, preserving the endpoint they did not supply. Keep the existing paired-period invariant for persisted Sprints and keep `sprint new` requiring both endpoints.

# **Implementation Plan**

- Carry independent start/end edit intent from the CLI through the service boundary.
- Merge a supplied endpoint with the existing counterpart before validating and saving.
- Add focused domain/service and CLI integration coverage for preservation and rejection paths.

# **Acceptance Criteria**

- [x] Updating only the start datetime changes the start datetime and preserves the existing end datetime.
- [x] Updating only the end datetime changes the end datetime and preserves the existing start datetime.
- [x] Updating both the start and end datetimes continues to succeed.
- [x] Invalid datetime input is rejected.
- [x] An update where the start datetime is later than the end datetime is rejected.
- [x] An update with neither datetime supplied preserves the existing behavior.
