# **Summary**

Harden Kanban runtime validation around terminal failures, restoration, and state transitions instead of relying on the aggregate line-coverage value alone.

# **Acceptance Criteria**

- [ ] Event interpretation and state transitions can be tested independently of terminal I/O and drawing.
- [ ] Regression tests cover drawing failure, event-reading failure, panic unwinding, narrow terminals, and repeated resize events.
- [ ] Tests verify that terminal modes and panic hooks are restored on every relevant exit path.
- [ ] CI applies a targeted guard for the Kanban runtime area, such as a module threshold or no-new-uncovered-lines rule, in addition to the repository-wide coverage gate.
- [ ] The documented test matrix identifies the important runtime failure paths and their verification method.
