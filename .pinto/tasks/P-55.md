Harden Kanban runtime validation around terminal failures, restoration, and state transitions instead of relying on the aggregate line-coverage value alone.

# **Implementation Plan**
## Runtime boundary
- Extract the frame and event-source boundary from the blocking loop so drawing, terminal sizing, polling, and event-reading failures can be injected without a real terminal.
- Keep event interpretation and the BoardView state model free of terminal and drawing dependencies, and cover their transitions with focused unit tests.
- Preserve the existing Kanban behavior and the async service calls used by mutations.

## Lifecycle safety
- Keep terminal and panic-hook ownership in scoped guards, and test normal returns, error returns, and panic unwinding.
- Make terminal restoration idempotent and retryable when a restoration attempt itself fails.

## Coverage and documentation
- Add a targeted Cobertura guard for the Kanban runtime package in addition to the repository-wide 95% gate.
- Document a runtime failure-path matrix covering sizing, drawing, polling, event reading, panic unwinding, narrow terminals, and repeated resize events.
- Validate with focused tests first, then the repository quality gates and CLI dogfooding.

## Plan update
- The first post-refactor coverage run exposed that moving key dispatch into its own module reduced the package rate until those branches were exercised.
- Extend the frame-driver boundary to cover editor handoff as well, then test confirmation, overlays, forms, search, board actions, and failure paths directly without a TTY.
- Keep the 0.90 package guard only after the focused dispatch tests make it pass; retain the repository-wide 0.95 guard.

# **Acceptance Criteria**
- [x] Event interpretation and state transitions can be tested independently of terminal I/O and drawing.
- [x] Regression tests cover drawing failure, event-reading failure, panic unwinding, narrow terminals, and repeated resize events.
- [x] Tests verify that terminal modes and panic hooks are restored on every relevant exit path.
- [x] CI applies a targeted guard for the Kanban runtime area, such as a module threshold or no-new-uncovered-lines rule, in addition to the repository-wide coverage gate.
- [x] The documented test matrix identifies the important runtime failure paths and their verification method.
