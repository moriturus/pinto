# **Summary**

Make deep parent/child and dependency traversals safe for large or malformed boards, preventing stack overflows while preserving deterministic output and diagnostics.

# **Implementation Approach**

The board load already holds every PBI in memory, so each traversal is bounded by the item count. The stack-overflow risk is purely the *native call stack* growing with chain depth in four recursive DFS helpers. The fix converts each to an explicit heap-allocated stack; nothing else about the observable output changes.

- **Hierarchical ordering** (`service::order::visit`): replace the recursive pre-order emit with an explicit stack. Push each node's children in reverse so they pop in input order, preserving the exact pre-order sequence. The `emitted` guard still breaks child-link cycles.
- **Kanban row layout** (`cli::kanban::layout::visit`): same explicit-stack pre-order, carrying `(index, depth, parent_index)` frames and only descending into expanded parents. Reverse-push children to keep sibling order and depth identical.
- **Point aggregation** (`service::points::Calculator`): replace the mutual recursion (`effective`/`contribution`/`sum_children`) with an explicit two-phase (enter/exit) post-order stack. The `visiting`/path set keeps cycle results `None`, and memoization is preserved. Uses the identity `contribution(c) = if c is a done leaf { Some(0) } else { effective(c) }` (a done non-leaf's `sum_children` already equals its `effective`), so only `effective` needs to be memoized. Each PBI has at most one parent, so the children graph has no diamonds and each node is computed once.
- **Dependency-cycle inspection** (`service::doctor::inspect::visit_graph`): rewrite the recursive Tarjan-style DFS as an explicit-stack iterative DFS while keeping the same three-state coloring and on-stack cycle extraction, so reported cycles are byte-for-byte identical and deterministically sorted. The `graph.rs` cycle *checks* are already iterative and unchanged.

Because traversal is now bounded by the in-memory item count and uses heap stacks, complete traversal always succeeds for any board that fits in memory; the visited-set guards guarantee deterministic, non-dropping behavior on malformed (cyclic) input. No arbitrary depth cap is introduced, since AC1 requires several-thousand-deep chains to succeed rather than fail.

# **Acceptance Criteria**

- [x] Hierarchical ordering, Kanban row layout, dependency-cycle inspection, and point aggregation handle synthetic chains several thousand levels deep without a stack overflow.
- [x] Traversal behavior remains deterministic and does not drop items or hide cycles when the input is malformed.
- [x] The implementation uses bounded, actionable failure behavior for depth or resource exhaustion when complete traversal is not possible.
- [x] Regression tests cover deep parent chains, deep dependency chains, and cyclic inputs through the relevant service and CLI paths.
