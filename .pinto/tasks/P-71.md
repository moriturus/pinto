# **Summary**

Include Sprint Retro and Review child records in machine-readable output and
board interchange so the new Sprint hierarchy remains complete, portable, and
Git-friendly across supported storage backends.

# **Implementation Plan**

## **JSON contract**

- Add an explicit `sprint_id` parent reference to Retro and Review JSON records while retaining every persisted field.
- Add `retros` and `reviews` collections to `export --json`; parse them back with the same IDs, parent links, timestamps, and Markdown bodies.
- Default missing child collections to empty arrays so snapshots created before this extension remain importable.

## **Snapshot and restore**

- Load both child-record repositories under the existing export board lock.
- Extend the import replacement boundary to remove stale Retro and Review records before writing the snapshot records.
- Keep the existing refusal and completion CLI messages stable unless the implementation requires a user-facing correction.

## **Persistence boundaries**

- Exercise File and Git plain-text persistence and the optional SQLite path, whose child records remain in the shared dedicated Markdown directories.
- Add migration regression coverage for the one-per-Sprint records and document the shared-directory invariant.

## **TDD and verification**

- Add failing CLI integration tests before implementation, then follow Red → Green → Refactor; combine them with the existing storage contract tests.
- Update the JSON schema, data-format documentation, and the export/import demos.
- Run focused tests, the required iterative-review passes, `mise run check`, CLI dogfooding, and complete P-71 only after all checks pass.

# **Scope**

- Extend child-record JSON output with the Sprint-matching IDs, parent Sprint
  reference, state, timestamps, and Markdown body.
- Include Retro and Review records in complete export --json snapshots and
  restore them through import.
- Preserve the records through supported storage migration and Git-backed
  mutation boundaries.
- Keep snapshots from boards without child records backward-compatible.

# **Acceptance Criteria**

- [x] Retro and Review show/list JSON output contains their parent Sprint
  reference and complete persisted record data.
- [x] export --json includes existing Retro and Review records, and import
  restores them without changing their IDs or parent links.
- [x] File, Git, and optional SQLite storage paths preserve the one-per-Sprint
  child records through their supported migration or persistence boundaries.
- [x] A board snapshot without Retro or Review records remains valid and imports
  as before.
- [x] Plain-text records and their JSON representation remain consistent and
  reviewable through Git.
