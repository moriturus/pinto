# **Summary**

Make Sprint removal refuse to orphan its one-to-one Retro or Review by default, while providing an explicit opt-in deletion option for removing the Sprint together with its existing child records.

# **Scope**

- Modify the existing Sprint removal command and its aliases without changing normal removal behavior when no child records exist.
- Detect either child record before mutation and report the blocking Retro or Review.
- Add a narrowly scoped, documented option that explicitly includes existing Retro and Review records in the deletion.
- Preserve the existing Git, recovery, and mutation-boundary guarantees for the combined deletion.

# **Acceptance Criteria**

- [ ] Sprint removal is rejected before mutation when a Retro or Review exists and the explicit inclusion option is absent.
- [ ] The rejection identifies the existing child records and explains how to request their deletion.
- [ ] An explicit inclusion option deletes the Sprint and any existing matching Retro and Review records together, without deleting unrelated records.
- [ ] Removing a Sprint with neither child record retains the existing behavior.
- [ ] The protected and explicit-deletion paths work consistently through the existing Sprint removal aliases and preserve recoverable Git history.
