# **Summary**

Make Sprint removal refuse to orphan its one-to-one Retro or Review by default, while providing an explicit opt-in deletion option for removing the Sprint together with its existing child records.

## **Implementation Plan**

- Service and CLI: extend `sprint remove` and `rm` with `--delete-records`; inspect matching Retro and Review before any mutation; default rejection names each present type and explains the opt-in command.
- Persistence and recovery: delete only matching child records when opted in, release assigned PBIs, and delete the Sprint under the existing lock and one Git commit; leave no-child behavior unchanged.
- Verification and delivery: use TDD for domain/service/CLI/Git/localization coverage, update docs and demo data, run iterative-review for at least two passes and `mise run check`, dogfood through `cargo run`, then complete P-68 and commit with its ID.

# **Scope**

- Modify the existing Sprint removal command and its aliases without changing normal removal behavior when no child records exist.
- Detect either child record before mutation and report the blocking Retro or Review.
- Add a narrowly scoped, documented option that explicitly includes existing Retro and Review records in the deletion.
- Preserve the existing Git, recovery, and mutation-boundary guarantees for the combined deletion.

# **Acceptance Criteria**

- [x] Sprint removal is rejected before mutation when a Retro or Review exists and the explicit inclusion option is absent.
- [x] The rejection identifies the existing child records and explains how to request their deletion.
- [x] An explicit inclusion option deletes the Sprint and any existing matching Retro and Review records together, without deleting unrelated records.
- [x] Removing a Sprint with neither child record retains the existing behavior.
- [x] The protected and explicit-deletion paths work consistently through the existing Sprint removal aliases and preserve recoverable Git history.
