# **Summary**

Document predictable failure behavior for the public Rust API so library users can understand validation, persistence, and retry contracts from Rustdoc.

# **Acceptance Criteria**

- [ ] Public destructive, multi-record, and persistence APIs include `# Errors` sections describing their relevant validation and I/O failures.
- [ ] The API documentation states whether durable partial changes may remain after failure and whether retrying is safe for the documented operations.
- [ ] A staged `missing_errors_doc` lint or equivalent guard prevents new omissions in the selected public API scope.
- [ ] Rustdoc and focused documentation tests verify that the documented error contracts remain consistent with the exposed result types and behavior.
