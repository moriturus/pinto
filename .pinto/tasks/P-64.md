# **Summary**

Allow authors to escape literal `automate` output-placeholder syntax when it must be passed as text, especially in non-item-ID arguments such as `--body`.

# **Implementation Plan**

## Escape syntax and resolution

- Use `@@command[...]` as the explicit escape form for a literal placeholder marker in any command argument.
- Make validation distinguish escaped markers from unescaped placeholders, while preserving complete output-reference validation in supported item-ID positions.
- Unescape `@@command` to `@command` immediately before executing the child command so the child receives the intended literal text.
- Keep malformed or unescaped placeholder-like text subject to the existing actionable diagnostics.

## Schema, tests, and documentation

- Update the automation JSON Schema and placeholder documentation so escaped literal markers are accepted as ordinary strings while real output references retain their existing form and constraints.
- Add Red/Green CLI regression coverage for multiline `--body` values in both dry-run and apply modes, literal output reaching the created item, continued resolution of real item-ID references, and invalid placeholder diagnostics.
- Run the focused automation tests, full repository checks, and CLI dogfooding before completing the item.

## Verification

- The automation CLI regression test verifies that escaped markers remain literal in apply output, dry-run does not mutate the board, and real item-ID references still resolve.
- The automation JSON Schema and CLI documentation describe the `@@command[...]` escape form and retain actionable validation for unescaped placeholder-like text in ordinary arguments.
- Focused tests, Clippy, formatting, documentation builds, and the full `mise run check` gate pass.
- CLI dogfooding confirms the PBI can be inspected, updated, and transitioned through the supported workflow.

# **Acceptance Criteria**

- [x] `automate` supports an explicit escape form for literal output-placeholder text in non-item-ID arguments.
