# **Summary**

Introduce an explicit Sprint Goal outcome and calculate the Sprint Goal Achievement Rate from Sprints whose goals have been evaluated.

# **Implementation Plan**

- Model the Sprint result as an optional boolean (goal_achieved = true or false), with None meaning unevaluated and serving as the clear operation; old and new records default to None without modifying the goal body.
- Persist the optional boolean as forward-compatible Sprint metadata in file, Git, SQLite, and export/import paths; old records and old snapshots default to unevaluated.
- Add a dedicated sprint goal report with recent-Sprint selection and human-readable/JSON output, counting only non-blank goals with a non-None result and reporting no rate when the denominator is zero; keep velocity and other reports untouched.
- Cover domain, file/SQLite/storage, service, CLI, JSON compatibility, and demo behavior with Red → Green → Refactor tests; verify through the repository quality gate and dogfooding.

# **Scope**

- Record whether a Sprint Goal was achieved, not achieved, or not yet evaluated.
- Keep the recorded outcome separate from the goal text, PBI completion, velocity, and other delivery metrics; do not infer the outcome from them.
- Allow an outcome to be set, changed, and cleared through the established Sprint management conventions.
- Provide a Sprint report that exposes each evaluated outcome and the aggregate achievement rate.
- Treat existing Sprints without an outcome, and Sprints without a non-blank goal, as unevaluated rather than failed.
- Preserve existing Sprint records and keep current velocity and other reports backward-compatible.

# **Acceptance Criteria**

- [x] A Sprint can persist an explicit goal outcome of achieved, not achieved, or unevaluated without changing the existing goal text.
- [x] The goal outcome can be set, updated, and cleared through the established Sprint CLI behavior with actionable validation errors.
- [x] Existing Sprint data without a stored outcome remains valid and is treated as unevaluated; a Sprint without a non-blank goal cannot inflate the failure count.
- [x] A Sprint report exposes the outcome for each selected Sprint and calculates the achievement rate as achieved evaluated Sprints divided by all evaluated Sprints, expressed as a percentage.
- [x] When no Sprint has an evaluated goal, the report communicates that the rate is unavailable instead of reporting zero percent.
- [x] Human-readable and JSON output expose the outcome and aggregate rate without changing the meaning of existing velocity, burndown, capacity, or cycle-time reports.
