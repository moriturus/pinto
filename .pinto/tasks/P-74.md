# **Summary**

The Sprint Goal outcome is masked to None at read time when the goal text is blank, which means the write path can persist an inconsistent state such as a blank goal alongside a recorded achievement. Move the invariant to the write side so a stored outcome always accompanies a non-blank goal, keeping the plain-text files internally consistent.

# **Acceptance Criteria**

- [ ] Recording a Goal outcome while the Sprint Goal is blank is rejected, or the stored outcome is cleared, at write time
- [ ] Read-side masking in the goal report and Sprint context becomes redundant given the enforced write-side invariant
- [ ] Persisted Sprint files never contain a recorded outcome next to a blank goal
- [ ] Tests cover editing a goal to blank after an outcome was recorded
