# **Summary**

The Sprint Goal outcome is masked to None at read time when the goal text is blank, which means the write path can persist an inconsistent state such as a blank goal alongside a recorded achievement. Move the invariant to the write side so a stored outcome always accompanies a non-blank goal, keeping the plain-text files internally consistent.

# **Implementation Plan**

## Domain invariant

- Normalize `goal_achieved` to `None` whenever the final Goal is blank, including when editing an existing Sprint or recording an outcome.
- Cover whitespace-only Goals and keep the explicit `true`/`false` outcome behavior unchanged for non-blank Goals.

## Persistence boundaries

- Normalize Sprint values before Markdown and SQLite writes so direct callers/imports cannot persist a blank Goal with an outcome.
- Keep Git behavior covered through its File repository delegation and add backend contract coverage.

## Read models

- Remove Goal-text checks from the Goal report and Sprint context; expose the stored outcome directly.
- Update API and documentation comments to describe the write-side invariant.

## Verification

- Add domain, CLI, and storage tests, including clearing a Goal after an outcome was recorded.
- Run focused tests, iterative review passes, and `mise run check`; then complete this item through the CLI.

# **Acceptance Criteria**

- [x] Recording a Goal outcome while the Sprint Goal is blank is rejected, or the stored outcome is cleared, at write time
- [x] Read-side masking in the goal report and Sprint context becomes redundant given the enforced write-side invariant
- [x] Persisted Sprint files never contain a recorded outcome next to a blank goal
- [x] Tests cover editing a goal to blank after an outcome was recorded
