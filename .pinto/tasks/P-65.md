# **Summary**

Extend `pinto` with Git-style external subcommand binaries that can provide nested commands while preserving built-in command precedence and a documented, versioned process contract.

# **Implementation Plan**

## Dispatch and resolution

- Allow unknown top-level commands to resolve to separately installed `pinto-*` executables, including nested names such as `pinto-team-report`.
- Validate command segments, select the longest matching executable, search beside the running binary before non-empty `PATH` entries, and never treat the current directory as an implicit search location.
- Keep built-in commands and their aliases authoritative so an external executable cannot shadow them.

## Process contract

- Forward each plugin argument as a separate argv element without shell interpolation.
- Forward an explicit `--dir` value as `PINTO_DIR`, provide `PINTO_HOST_VERSION` and `PINTO_PLUGIN_CONTRACT_VERSION=1`, and preserve the child process exit code.
- Allow external commands and root help discovery to operate without first opening or initializing a board; keep missing-command failures user-facing.

## Help, compatibility, and documentation

- Discover external commands for root help, use bounded `--help` summaries, omit broken or slow candidates, and localize the external-command heading.
- Define the trust model, naming and resolution rules, process environment, versioning, argv boundary, automation boundary, and plain-text `.pinto` compatibility boundary in `docs/plugin-contract.md`.
- Provide a runnable external-command demo and document the feature in the design record and CLI book.

## Verification

- Added CLI and unit coverage for nested dispatch, longest-prefix resolution, executable precedence, implicit-current-directory exclusion, argv and environment forwarding, help discovery, missing commands, and child exit codes.
- Verified that `automate` handles external commands without applying item-ID placeholder validation to their arguments.
- Focused external-subcommand integration tests pass, and the documented contract, demo, and CLI help behavior are included with the implementation.

# **Acceptance Criteria**

- [x] Unknown top-level and nested commands resolve to valid `pinto-*` executables using the longest matching prefix.
- [x] Executable discovery checks the directory beside `pinto` before non-empty `PATH` entries, does not add the current directory implicitly, and never lets an external command shadow a built-in command or alias.
- [x] External processes receive exact argv forwarding, the documented `PINTO_DIR` and version environment variables, and their exit status is propagated without requiring an initialized board.
- [x] Root help lists responsive external commands with concise summaries, while broken or slow plugins are omitted and missing commands produce a clear user error.
- [x] The versioned plugin contract, trust and file-format boundaries, automation boundary, runnable demo, localized help heading, and regression coverage are documented or implemented.
