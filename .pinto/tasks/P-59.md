# **Summary**

Create GitHub Releases automatically from the repository's `CHANGELOG` so tagged releases can be published without manually creating the release entry.

# **Implementation plan**

1. Add a small, POSIX-compatible release-notes extractor that selects the dated `CHANGELOG.md` section matching the release tag and fails clearly when the tag has no matching entry.
2. Extend the tag-only release workflow with the minimum `contents: write` permission and use the runner-provided GitHub CLI to create the release from the extracted notes after the existing release checks pass.
3. Follow Red → Green → Refactor with integration coverage for matching, missing, and boundary release-note sections without adding brittle assertions over unrelated workflow prose.
4. Update the release/local-CI documentation and add a reproducible demo README/data path for the CHANGELOG-backed release creation flow.
5. Run focused script/integration checks, `actionlint`, `mise run check`, iterative review passes, and Windows verification before completing this item through the Pinto CLI.

# **Acceptance Criteria**

- [x] A release tag automatically creates the corresponding GitHub Release.
- [x] The generated GitHub Release notes are sourced from the matching `CHANGELOG` entry.
- [x] The release workflow does not require manual GitHub Release creation.
