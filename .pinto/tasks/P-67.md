# **Summary**

Add one first-class Sprint Review record beneath each existing Sprint. A Review uses the Sprint ID as its own ID, is stored in the dedicated `.pinto/review/` directory, and follows the established PBI and Sprint CLI conventions for creation, templates, editing, display, listing, and machine-readable output.

## **Implementation Plan**

### Domain and persistence

- Add a `SprintReview` domain record with the parent Sprint ID as its identity and Markdown body timestamps.
- Add Review repositories for the file, Git, and optional SQLite backends under the dedicated `.pinto/review/` directory.
- Preserve the one-Review-per-Sprint invariant and keep Review data independent from Sprint goals and Retro records.

### Service and CLI

- Expose creation, editing, display, listing, and JSON output only through `pinto sprint review`, including the existing direct Sprint-ID creation shorthand.
- Require an existing parent Sprint while accepting planned, active, and closed parent Sprint states; Review has no state of its own.
- Support `.pinto/templates/review/<name>.md`, `--template`, and standard-editor creation/editing with the selected template as initial content.

### Verification and delivery

- Follow Red → Green → Refactor with domain, backend contract, CLI, localization, Git-boundary, and demo coverage.
- Update the CLI/data-format/JSON documentation and add a runnable `demos/single/sprint-review` fixture.
- Run focused tests, `iterative-review` for at least two review/fix/test passes, and `mise run check`; verify the feature through `cargo run` dogfooding before completing P-67 and committing with the item ID.

# **Scope**

- Expose the feature under `pinto sprint review`; do not add a top-level `pinto review` command.
- Allow at most one Review for each Sprint, with the Review ID and filename equal to the Sprint ID.
- Require the referenced Sprint to exist, but allow creation when that parent Sprint is planned, active, or closed.
- Support `.pinto/templates/review/<name>.md`, `--template`, and standard-editor editing with the same creation and edit semantics as PBIs.
- Keep Review data separate from the Sprint goal and from the Retro record while following existing output, localization, error, Git-boundary, and JSON conventions.

# **Acceptance Criteria**

- [x] `pinto sprint review` is the supported command path and no top-level `pinto review` command is required.
- [x] A Sprint can have zero or one Review, and the stored Review ID and filename match the Sprint ID.
- [x] Review creation succeeds for an existing Sprint in planned, active, and closed states and fails clearly when the Sprint does not exist.
- [x] Review creation accepts `--template <name>` from `.pinto/templates/review/<name>.md`, and `--edit` opens the configured standard editor with the template as initial content when supplied.
- [x] Review edit, show, list, and JSON behavior follows the established PBI or Sprint conventions, including actionable errors and localized output.
