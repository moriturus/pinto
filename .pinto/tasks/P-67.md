# **Summary**

Add one first-class Sprint Review record beneath each existing Sprint. A Review uses the Sprint ID as its own ID, is stored in the dedicated `.pinto/review/` directory, and follows the established PBI and Sprint CLI conventions for creation, templates, editing, display, listing, and machine-readable output.

# **Scope**

- Expose the feature under `pinto sprint review`; do not add a top-level `pinto review` command.
- Allow at most one Review for each Sprint, with the Review ID and filename equal to the Sprint ID.
- Require the referenced Sprint to exist, but allow creation when that Sprint is planned, active, or closed.
- Support `.pinto/templates/review/<name>.md`, `--template`, and standard-editor editing with the same creation and edit semantics as PBIs.
- Keep Review data separate from the Sprint goal and from the Retro record while following existing output, localization, error, Git-boundary, and JSON conventions.

# **Acceptance Criteria**

- [ ] `pinto sprint review` is the supported command path and no top-level `pinto review` command is required.
- [ ] A Sprint can have zero or one Review, and the stored Review ID and filename match the Sprint ID.
- [ ] Review creation succeeds for an existing Sprint in planned, active, and closed states and fails clearly when the Sprint does not exist.
- [ ] Review creation accepts `--template <name>` from `.pinto/templates/review/<name>.md`, and `--edit` opens the configured standard editor with the template as initial content when supplied.
- [ ] Review edit, show, list, and JSON behavior follows the established PBI or Sprint conventions, including actionable errors and localized output.
