# **Summary**

Define and enforce an operation-level persistence contract for multi-record mutations such as PBI splitting and forced snapshot import, so a failure during a write cannot silently leave orphaned or mixed board state.

# **Acceptance Criteria**

- [ ] `split` and `import --force` document whether they complete atomically or which scoped recovery protocol applies for the File, Git, and SQLite backends.
- [ ] SQLite execution for each supported multi-record operation uses one transaction boundary where the backend supports it.
- [ ] File and Git executions preserve a pre-operation recovery point and restore or clearly expose a recoverable state when a later write fails.
- [ ] Deterministic failure-injection tests cover failures after an early record write and verify the documented post-failure state for both operations.
- [ ] CLI and user documentation provide actionable retry or recovery guidance.
