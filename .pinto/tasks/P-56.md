# **Summary**

Define and enforce an operation-level persistence contract for multi-record mutations such as PBI splitting and forced snapshot import, so a failure during a write cannot silently leave orphaned or mixed board state.

# **Implementation Plan**

- Introduce operation-scoped persistence APIs for split and forced import so each service operation prepares its complete target state before applying it.
- Use one SQLite transaction for each operation, including active-item replacement, sprint replacement, and item relationships; keep configuration and DoD changes inside the same recoverable import protocol.
- Add File/Git recovery points around multi-record writes. Restore the pre-operation board after a write failure; preserve Git commit-failure changes as an explicitly recoverable worktree state with actionable diagnostics.
- Add deterministic test-only write-failure injection after an early record write, covering split and forced import on File, Git, and SQLite where available.
- Update CLI help/errors, stability guidance, the book, and a focused demo with retry/recovery commands. Re-run the focused tests, iterative review, mise run check, and dogfood both successful operations before completion.

# **Acceptance Criteria**

- [x] split and import --force document whether they complete atomically or which scoped recovery protocol applies for the File, Git, and SQLite backends.
- [x] SQLite execution for each supported multi-record operation uses one transaction boundary where the backend supports it.
- [x] File and Git executions preserve a pre-operation recovery point and restore or clearly expose a recoverable state when a later write fails.
- [x] Deterministic failure-injection tests cover failures after an early record write and verify the documented post-failure state for both operations.
- [x] CLI and user documentation provide actionable retry or recovery guidance.
