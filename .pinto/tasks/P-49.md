# **Summary**

Add a PBI splitting feature that is available in Kanban mode and creates new PBIs from an existing item, with optional dependency or parent-child relationships. Copy the source body by default, while allowing the caller to choose an empty body, a template body, or an explicitly supplied body.

# **Implementation Plan**

## Service layer (`src/service/item/split.rs`)

Add `split_item(project_dir, source, SplitSpec) -> Result<SplitOutcome>`, re-exported from `src/service.rs`.

- `SplitSpec { titles: Vec<String>, relationship: SplitRelationship, body: SplitBody }`.
- `SplitRelationship { None, Child, Dependency }` — mutually exclusive. `Child` makes the source the parent of each new PBI; `Dependency` makes the source depend on each new PBI.
- `SplitBody { Copy, Empty, Explicit(String) }` — `Copy` (default) duplicates the source body; a resolved template is passed as `Explicit`.
- Implementation mirrors `add_item_with_outcome`: lock the board, look up the source (`NotFound` otherwise), resolve the body once, then for each title mint an id, append a rank after the running last, set status to the first workflow column, apply the relationship, and save. For `Dependency`, append the new ids to the source's `depends_on` and save the source. Commit once (`pinto: split <source> into <ids>`). Splitting cannot introduce a cycle (new items have no other edges), so no cycle warning is produced.

## CLI (`pinto split`)

`split <SOURCE> <TITLE>...` with short forms for every option:
- `--child/-c` and `--dependency/-d` (mutually exclusive) select the relationship.
- `--body/-b`, `--template/-t`, `--empty/-e` (mutually exclusive) select the body; the default copies the source body.

Handler `cmd_split` resolves the body (template via `template_body`), calls `split_item`, and prints one localized `split-created` line per new PBI.

## Kanban integration

New `KeyAction::Split` (default `s`). `begin_split()` captures the selected source. A multi-step form (reusing the existing text-entry loop) collects: title, relationship (`Enter`/`n`=none, `c`=child, `d`=dependency), and body option (`Enter`/`c`=copy, `e`=empty, `t`=text, `m`=template; `t`/`m` add a follow-up text step). Kanban creates one new PBI per invocation. `InputSubmission::Split` is persisted through `split_item` in `runtime/actions.rs`, then the board is rebuilt and a status message shown.

## i18n / docs / demos

Add `Message` variants and `en-US`/`ja-JP` Fluent entries for the CLI command/args, the `split-created` line, and the Kanban prompts/status messages. Add `demos/` data and a `README.md`, and document the command and key binding in the book.

# **Acceptance Criteria**

- [x] An existing PBI can be split into one or more new PBIs.
- [x] Kanban mode exposes PBI splitting and applies the selected relationship and body options.
- [x] The split operation can optionally create dependency relationships for the resulting PBIs.
- [x] The split operation can optionally create parent-child relationships between the source and resulting PBIs.
- [x] New PBI bodies copy the source body by default.
- [x] The split operation supports selecting an empty body, a template body, or an explicitly supplied body.
