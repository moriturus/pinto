# **Summary**

SprintRetro and SprintReview are byte-for-byte identical after a retro/review symbol substitution across the domain, service, storage (file and SQLite), backend dispatch, error, i18n, CLI, and JSON layers. Consolidate them into a single record type carrying a kind discriminant, mirroring the existing ActionSourceKind enum, so the duplicated parallel stacks collapse into one code path while the records keep their separate on-disk directories.

# **Acceptance Criteria**

- [ ] A single kind-tagged Sprint record type replaces SprintRetro and SprintReview across the domain, service, and storage layers
- [ ] Retro and Review records continue to serialize to their existing on-disk locations, preserving backward compatibility
- [ ] Backend dispatch, error variants, JSON DTOs, and i18n keys are expressed once and parameterized by kind
- [ ] Existing retro, review, export/import, and delete-protection tests keep passing with unchanged behavior
