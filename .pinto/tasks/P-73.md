# **Summary**

SprintRetro and SprintReview are byte-for-byte identical after a retro/review symbol substitution across the domain, service, storage (file and SQLite), backend dispatch, error, i18n, CLI, and JSON layers. Consolidate them into a single record type carrying a kind discriminant, mirroring the existing ActionSourceKind enum, so the duplicated parallel stacks collapse into one code path while the records keep their separate on-disk directories.

# **Implementation Plan**

## Domain model and kind

Introduce one `SprintRecord` with a `SprintRecordKind::{Retro, Review}` discriminant and reuse that kind for action-source links. Keep the Sprint ID, Markdown body, and timestamps unchanged.

## Repository and service

Replace the parallel Retro/Review repository traits and modules with one kind-parameterized repository contract and one service implementation. Derive the storage directory, filename validation, parse diagnostics, and Git/SQLite delegation from the record kind.

## CLI, JSON, errors, and localization

Keep the existing `sprint retro` and `sprint review` command shapes and JSON export keys, but route them through shared kind-parameterized helpers. Consolidate record JSON conversion, error variants, and Fluent message IDs while preserving existing English/Japanese output.

## Compatibility and verification

Preserve the `.pinto/retro/<SPRINT-ID>.md` and `.pinto/review/<SPRINT-ID>.md` formats and all observable behavior. Follow Red → Green → Refactor, run focused and all-feature checks, perform the required iterative review, dogfood both commands, then complete P-73 through the Pinto CLI.

# **Acceptance Criteria**

- [x] A single kind-tagged Sprint record type replaces SprintRetro and SprintReview across the domain, service, and storage layers
- [x] Retro and Review records continue to serialize to their existing on-disk locations, preserving backward compatibility
- [x] Backend dispatch, error variants, JSON DTOs, and i18n keys are expressed once and parameterized by kind
- [x] Existing retro, review, export/import, and delete-protection tests keep passing with unchanged behavior
