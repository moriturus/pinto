# **Summary**

Make Retro and Review records useful for Sprint inspection by exposing the parent Sprint's existing goal, schedule, state, and available delivery metrics without requiring users to duplicate that context in Markdown.

# **Scope**

- Reuse existing Sprint lifecycle, velocity, burndown, capacity, cycle-time, and spillover information where it is available.
- Keep generated Sprint context separate from user-authored Retro and Review Markdown.
- Preserve close-time historical context after unfinished work is rolled over or released.
- Present unavailable metrics explicitly rather than inventing values for planned or incomplete Sprints.

# **Acceptance Criteria**

- [ ] Retro and Review views expose the parent Sprint's goal, state, schedule, and relevant available delivery context.
- [ ] Existing velocity, burndown, capacity, cycle-time, and spillover semantics are reused without creating a second metric system.
- [ ] Generated context is distinguishable from and does not overwrite user-authored Markdown.
- [ ] Close-time spillover and other historical values remain understandable after unfinished PBIs change Sprint assignment.
- [ ] Planned or incomplete Sprints report unavailable context clearly instead of showing misleading zero values.
