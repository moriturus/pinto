# **Summary**

Make Retro and Review records useful for Sprint inspection by exposing the existing parent Sprint goal, schedule, state, and available delivery metrics without requiring users to duplicate that context in Markdown.

## **Implementation Plan**

### Context model and existing metrics

- Add a read-only Sprint Context service view that loads the parent Sprint and assigned PBIs, exposes the existing goal, state, schedule, close timestamp, and spillover snapshot, and reuses the existing capacity, velocity, burndown, and cycle-time aggregation logic.
- Keep unavailable metrics as explicit optional values; do not turn planned or incomplete delivery into synthetic zeroes. A closed Sprint keeps its close-time spillover and completed-work history even when unfinished PBIs were rolled over or released.

### Retro and Review views

- Enrich the default `sprint retro show` and `sprint review show` human views with a clearly marked generated Sprint Context section; keep the authored Markdown body separate and keep `--plain` body-only.
- Add the same generated context as a nested machine-readable JSON field without persisting it in Retro or Review Markdown, and keep Review without a state of its own.

### Verification and delivery

- Follow Red -> Green -> Refactor with service, human/JSON CLI, close rollover/release, unavailable-metric, and both Retro/Review coverage.
- Add a focused demo and update the CLI, JSON, and data-format documentation; run iterative-review for at least two passes, `mise run check`, and cargo-run dogfooding before completing P-69 and committing with the item ID.

# **Scope**

- Reuse existing Sprint lifecycle, velocity, burndown, capacity, cycle-time, and spillover information where it is available.
- Keep generated Sprint context separate from user-authored Retro and Review Markdown.
- Preserve close-time historical context after unfinished work is rolled over or released.
- Present unavailable metrics explicitly rather than inventing values for planned or incomplete Sprints.

# **Acceptance Criteria**

- [x] Retro and Review views expose the parent Sprint goal, state, schedule, and relevant available delivery context.
- [x] Existing velocity, burndown, capacity, cycle-time, and spillover semantics are reused without creating a second metric system.
- [x] Generated context is distinguishable from and does not overwrite user-authored Markdown.
- [x] Close-time spillover and other historical values remain understandable after unfinished PBIs change Sprint assignment.
- [x] Planned or incomplete Sprints report unavailable context clearly instead of showing misleading zero values.
