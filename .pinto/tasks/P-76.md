# **Summary**

The domain error enum carries CLI-shaped usage errors (the requires-a-Sprint-ID-or-nested-operation cases that point at --help) which describe argument-parsing outcomes rather than domain failures. Relocate them to the CLI layer so the domain error type stays independent of CLI input shape and testable in isolation.

# **Implementation Plan**

## CLI boundary

- Define a CLI-only usage error for a missing Sprint child-record operation or ID.
- Format it through the existing Fluent message and classify it as a user error so exit code and English/Japanese guidance remain unchanged.

## Domain cleanup

- Remove the command-usage variant and its code, localization, user-error classification, and domain test fixtures from `pinto::error::Error`.
- Keep `SprintRecordKind` and persistence/service errors in the domain layer because they describe records rather than CLI argument shape.

## Compatibility

- Preserve the exact no-argument Retro and Review text, including the `--help` guidance, through the CLI error path.
- Keep the existing message catalog entry as a UI concern used by the CLI boundary.

## Verification

- Use a CLI-layer localization unit test plus Retro/Review no-argument integration tests.
- Run Clippy, focused tests, iterative-review passes, and `mise run check`; then complete P-76 through the CLI.

# **Acceptance Criteria**

- [x] Command-usage error variants no longer live in the domain error enum
- [x] The sprint retro and sprint review no-argument guidance is produced at the CLI layer
- [x] Domain error tests no longer reference CLI-usage variants
- [x] User-facing behavior and messages for the no-argument case stay unchanged
