# **Summary**

Automate dependency and GitHub Actions maintenance so security and compatibility
updates are proposed, reviewable, and protected against untracked drift.

# **Acceptance Criteria**

- [x] Every GitHub Actions reference is pinned to a full commit SHA and retains a human-readable version comment.
- [x] Scheduled automation proposes updates for Cargo dependencies and GitHub Actions.
- [x] The deprecated test-only YAML dependency is replaced with a maintained parser or covered by an explicit, reviewed compatibility decision.
- [x] The dependency policy records approved duplicate versions and detects newly introduced duplicates.
- [x] Maintainer documentation explains how to review and validate automated update proposals.

# Implementation Plan

## AC1 — SHA-pin every GitHub Actions reference (and bump to latest)

Rewrite each `uses: owner/repo@vTag` in `.github/workflows/ci.yml` and
`.github/workflows/pages.yml` to `uses: owner/repo@<40-char-sha> # vTag`, where
the SHA resolves the *latest* release of that action (per user request to bump
while pinning). `dtolnay/rust-toolchain@stable`/`@nightly` infer the toolchain
from the git ref, which is lost once pinned to a SHA, so add explicit
`with: toolchain: stable|nightly` to those steps.

## AC2 — Dependabot proposals for Cargo and Actions

Add `.github/dependabot.yml` with weekly update schedules for the `cargo` and
`github-actions` ecosystems (grouped minor/patch updates, bounded open-PR
counts) so security and compatibility updates are proposed automatically.

## AC3 — Replace the deprecated test-only YAML parser

`serde_yaml` (0.9.34) is archived/unmaintained. Its only use is the dev-only
YAML structural check in `tests/docs.rs`. Replace it with the actively
maintained `yaml-rust2` parser (`YamlLoader::load_from_str`), keeping the
dependency dev-only, and record the decision in `docs/dependencies.md`.

## AC4 — Duplicate-version dependency policy

Set `deny.toml [bans] multiple-versions = "deny"` and record the currently
approved duplicates (`hashbrown` 0.16/0.17, `unicode-width` 0.1/0.2) as `skip`
entries with rationale. Any newly introduced, unrecorded duplicate then fails
`mise run deny`.

## AC5 — Maintainer documentation

Document in `docs/dependencies.md` how a maintainer reviews and validates an
automated update proposal: confirm the SHA pin and version comment, run
`mise run check` / `mise run audit` / `mise run deny`, and record or reject any
newly introduced duplicate versions.

## Definition of Done

- Integration test (`tests/dependency_automation.rs`) asserts: all workflow
  `uses:` are SHA-pinned with version comments; `dependabot.yml` covers both
  ecosystems on a schedule; `deny.toml` denies duplicates and records the
  approved skips; the maintainer docs are present.
- `mise run check` (test / lint / docs / fmt) passes; behavior dogfooded via
  `cargo run`.
