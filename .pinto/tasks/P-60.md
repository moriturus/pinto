# **Summary**

Organize GitHub Actions into focused workflows and trigger each one only for events and branches that require its jobs.

# **Implementation plan**

1. Keep `.github/workflows/ci.yml` focused on change-triggered compatibility and quality checks for pushes to `main` and `develop` and for pull requests; keep Pages deployment separate and move release, benchmark, and scheduled fuzz responsibilities into dedicated workflows.
2. Establish a Red workflow contract using `actionlint`, `act -l`, and event-specific `act` dry-runs or local runs to verify that each supported event exposes only the relevant jobs, without adding Rust tests that inspect workflow text.
3. Split the existing jobs with the smallest responsibility-preserving moves: release packaging only for semantic-version tags, normal benchmark smoke only for branch pushes and pull requests, scheduled benchmarks and fuzz only for the weekly schedule, and dependency policy/coverage retained on the change-validation path as appropriate.
4. Update local-CI and reproducibility guidance and any existing workflow references, run focused validation plus `mise run check`, perform at least two iterative-review passes, then complete P-60 through the Pinto CLI.

# **Acceptance Criteria**

- [ ] Workflows are separated by responsibility so unrelated jobs are not run together.
- [ ] Pushes to `main` and `develop`, pull request events, and tag pushes are covered by the appropriate workflows.
- [ ] Each supported event executes only its relevant jobs, without starting unrelated jobs.
