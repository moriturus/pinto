# **Summary**

Make large-board performance measurements detect meaningful regressions in CI while preserving reproducible benchmark evidence.

# **Acceptance Criteria**

- [ ] A repeatable benchmark measures `list`, `show`, `add`, `move`, `doctor`, and `import` on boards with at least 1,000 and 10,000 items.
- [ ] The 1,000-item smoke benchmark runs on a regular CI path, while the 10,000-item benchmark runs on a scheduled path and stores median results with the execution environment.
- [ ] Regression detection compares results with a recent baseline and an explicit tolerance rather than relying only on fixed absolute time limits.
- [ ] A performance failure identifies the affected command, baseline, measured result, and benchmark environment.
- [ ] Benchmark documentation describes the measurement method, retention, and interpretation of the results.
