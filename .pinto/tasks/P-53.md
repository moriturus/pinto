# **Summary**

Make large-board performance measurements detect meaningful regressions in CI while preserving reproducible benchmark evidence.

# **Implementation Plan**

## Benchmark runner

Extend `large_board_bench` to measure `list`, `show`, `add`, `move`, `doctor`, and `import` on fresh file-backend boards containing 1,000 and 10,000 items. Keep setup outside the timed command and record every sample plus its median.

## Scalability prerequisite

The first 10,000-item run exposed unbounded `doctor` file reads hitting common descriptor limits. Bound that read fan-out with the same asynchronous I/O discipline used by the file repository, and protect the executable 1,000-item path with an integration regression test before recording the large-board baseline.

## Regression contract

Emit a machine-readable JSON report containing the selected sizes, command medians, sample values, and execution environment. Compare the report with the committed recent baseline using an explicit percentage tolerance; report the command, board size, baseline, measured result, delta, and environment before failing.

## CI and retention

Run the 1,000-item smoke benchmark on the regular Ubuntu CI path and the 10,000-item benchmark only on the scheduled path. Save each JSON report as a GitHub Actions artifact with retention metadata.

## Documentation and demo

Update the benchmark guide and demo README with the measurement method, baseline update workflow, artifact retention, and interpretation of environment-dependent medians. Preserve the existing small demo board.

## Verification

Add integration contract coverage for the runner options, JSON/report schema, regression diagnostic, CI split, and documentation. Run focused benchmark checks followed by `mise run check`, dogfood the benchmark through the current checkout CLI, then complete P-53 only after iterative review.

# **Acceptance Criteria**

- [x] A repeatable benchmark measures `list`, `show`, `add`, `move`, `doctor`, and `import` on boards with at least 1,000 and 10,000 items.
- [x] The 1,000-item smoke benchmark runs on a regular CI path, while the 10,000-item benchmark runs on a scheduled path and stores median results with the execution environment.
- [x] Regression detection compares results with a recent baseline and an explicit tolerance rather than relying only on fixed absolute time limits.
- [x] A performance failure identifies the affected command, baseline, measured result, and benchmark environment.
- [x] Benchmark documentation describes the measurement method, retention, and interpretation of the results.
